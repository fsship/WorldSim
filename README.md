# WorldSim · 世界剧场

一个可在本机游玩的中文单人世界模拟器。《王宫疑云》从一份调防令开始，《雾港来信》要查明雾里的第二束灯光，《震后一周》从答应妈妈下班回家吃饭的周一早晨开始。也可以自己写剧本来玩。

## 启动

需要 Node.js **22.18 或更高版本**，本项目在 Node 22.21 上验证，使用 pnpm 10.22 与 Node 原生 SQLite。以下命令适用于 macOS / Linux。

```sh
pnpm install
pnpm dev
```

在浏览器打开 [WorldSim 本地游戏](http://127.0.0.1:5173/)。Vite 在 5173 端口提供页面，并把同源的 `/api` 转发给 3001 端口的 Fastify。没有存档时先选择剧本，有存档时优先恢复这个浏览器上次玩的游戏。默认使用确定性的 Mock，启动时无需配置密钥。

如果 Node 附带 Corepack 但找不到 `pnpm`，可直接使用 `corepack pnpm install` 和 `corepack pnpm dev`。第一次安装需要访问 npm registry。

**自定义剧本**。在剧本库点「自定义剧本」，只填写世界信息和当下处境就可以开始，不必先写人物名单。例如，世界信息写“海港的渡轮凭纸票登船”，当下处境写“我刚走进售票亭，有人从窗口递出一张船票”。使用真实模型时，剧情第一次需要这个人出场，模型才给出姓名、身份与职责。独处或空场也可以继续。遇见的人会成为存档内的角色，之后能听见你的话、再次交谈，载入快照仍是同一个人。默认的本地 Mock 提供离线演示。要使用模型生成角色，在「模型设置」中选择兼容服务。

也可以预先指定标题、开场时间、地点、玩家、固定 NPC 与剧情事件。地点按列表顺序前后相连。局部事件由在场角色目击，公共通告可以传到异地。修改剧本只影响之后新开的游戏，每个旧存档和快照都保有自己的世界。

在「新建游戏」选择《震后一周》，可体验一次持续影响通勤与家人的强震。打开「世界状态」可查看最近确认的路况、工作室状况和此前的决定。点击可选行动会把它填到输入框，也可以直接用自己的话描述想做的事。

**试着玩一回合**。在《王宫疑云》中输入「我走到档案室」，再输入「查阅值夜登记簿」。地点、时间和已知事实会随实际行动更新。输入「我取出背包里的核弹」可以验证物品前置条件。「时间控制」可以等待指定分钟、休息到某一时刻或等待事件。重要消息出现时，控制权会提前交还给你。

在议事厅输入「看看长桌上的朝会议程」，世界纪事会逐项显示纸上写的内容。也可以在一句话里向艾琳问早，顺手看议程；只有引号里的话会被在场的人听见。每项耗时一分钟，如果读到一半听见钟声或接到重要通报，可以用「继续读」从停下的位置接着看，或用「看下一项」只读一项。

**保存与恢复**。每次成功处理的行动都会自动保存；「存档管理」可以创建快照、切换游戏。载入快照会建立独立分支，复制该时刻的世界和此前回合。要备份全部游戏，请先停止服务，复制整个 `data/` 目录。浏览器本地存储只记录上次玩的游戏 ID。

如果最后一回合的问话已经传到现场，但 NPC 答复生成失败，可以在纪事里点「重试某人的答复」。原听众和现场仍可还原时，游戏会补上这句回答，保留当时的时间、发言及已经发生的动作。

## 模型与部署

服务端从仓库根目录读取可选的 `.env`。复制 `.env.example` 后可设置以下变量，也可以在页面的「模型设置」里切换引擎。

| 设置 | 默认值与作用 |
| --- | --- |
| `LLM_MODE` | `mock` 离线模拟，`openai` 使用兼容 HTTP 服务 |
| `LLM_BASE_URL` | `https://api.openai.com/v1`，也可使用本机 HTTP 模型端点。填写 API 前缀，程序会拼接 `/chat/completions` |
| `LLM_MODEL`、`LLM_API_KEY` | 模型默认为 `gpt-4o-mini`。填写目标端点支持的模型，以及该端点要求的密钥 |
| `LLM_TEMPERATURE`、`LLM_MAX_TOKENS` | 默认为 0.3、800 |
| `LLM_TIMEOUT_MS`、`LLM_RETRIES` | 单次请求默认 30 秒超时，默认允许额外重试 1 次，可配置 0～3 次 |
| `DATABASE_PATH` | 默认 `data/worldsim.sqlite`，相对路径基于仓库根目录 |
| `PORT` | 后端端口，默认 3001，开发代理使用同一端口 |

界面保存后的设置优先于环境变量，存放于服务端 SQLite 的专用表。密钥只在配置写入时发送给本机后端，读取配置仅返回是否已有密钥。更换 Base URL 时，需要为新端点单独填写密钥。数据库以本机用户读写权限保存，包括模型密钥，备份也应按机密文件保管。

**查看模型调用**。打开「管理 → 模型调用记录」，或直接访问 [本地调用记录页](http://127.0.0.1:5173/llm-calls)。可以按请求或响应正文、任务名、模型、存档或调用 ID 搜索，再按成功或失败筛选。点开一条记录可以查看发出的提示词、响应原文、耗时、HTTP 状态和服务商返回的 token 用量。详情中的「查看各次尝试」会列出同一次调用的重试。

每次实际 HTTP 请求结束后会单独写入本机 SQLite，包括失败回合和自动重试。开场对应第 0 回合。记录从升级后开始，离线 Mock 不产生 HTTP 调用。单次响应最多保存 512 KiB，详情会标记被截断的正文。请求头不写入日志，配置的 API 密钥会在正文中遮盖。

兼容端点需要接受 JSON 对象模式和 `max_completion_tokens`。如果端点明确用 HTTP 400 拒绝 `temperature`，Provider 会省略该参数并重发一次，采用模型默认采样设置。本回合后续模型调用沿用这个选择。这次兼容重发独立于 `LLM_RETRIES`。行动解析、开放行动裁决、NPC 自主决策、自由动作和台词的生成与审查、观察叙事均按任务分开请求。模型看到的内容会交给你所配置的服务商处理。[OpenAI Chat Completions 接口文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)

本机构建并运行单端口发布版本：

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

打开 [WorldSim 本地发布版本](http://127.0.0.1:3001/)。Fastify 同时提供构建后的页面和游戏 API。运行服务时保留 workspace、依赖和 Web 构建产物。服务仅监听回环地址，适用于一个受信任的本机玩家。

## 实现

| 目录 | 职责 |
| --- | --- |
| `packages/shared` | Zod 契约、可序列化的客观世界、公开状态、回合记录、模型任务接口 |
| `packages/engine` | 行动前置条件、候选裁决、状态变更验证、事件提交、时间队列、感知过滤与叙事编排 |
| `packages/scenarios` | 内置剧本目录、王宫与河谷剧情、可编辑剧本的世界初始化 |
| `packages/llm` | Mock 与可替换的 Chat Completions Provider、分任务提示、严格响应验证、限时与有限重试 |
| `apps/server` | Fastify、Drizzle、SQLite 事务、幂等、存档与快照、密钥配置 |
| `apps/web` | React、Vite、Tailwind，世界纪事、输入栏、玩家状态、历史与游戏管理 |

### 每回合如何执行

1. 配置真实模型后，每个回合先把玩家原话、所在场景和可指称的对象交给模型。模型判断行动者、目的、对象、说出的原话，以及随口问候时顺手阅读之类的组合，然后返回结构化回合计划。引擎依据计划里的对象 ID 检查持有权、位置、权限、可见范围和时间，成功处理的计划随该回合保存。明确的引语与行动必须各有原文依据。接口失败会保留存档；离线 Mock 和旧接口在自己的兼容路径中使用本地中文解析。
2. 玩家搭话或下令时，模型以实际听者的视角决定如何回应。移动、阅读、交谈和等待共用世界时钟。每逢五分钟刻度，同地和相邻地点最多两位重要角色获得个人行动机会。国王正在赶路时，以路程两端计算邻近范围。
3. 旅途有出发与抵达两个时刻。途中可以听见沿途的钟声，抵达后才能看到目的地里的人。NPC 从某地离开或进入一处房间时，两个地点各自记录当时的见证人。世界状态、角色行动、听众和玩家所见都随同一个回合提交。
4. 引擎把发生地、可听范围、公开性、被告知者和已知事实作为披露条件。它分别构造 NPC 的知识上下文、玩家界面和叙事输入。
5. 开场 NPC 会自行决定是否说话。需要开口时（也可先做动作再开口），模型根据已执行的动作、对话历史与允许披露的事实生成台词。服务端验证台词结构和引用，再用单独的模型请求审查事实依据、引用准确性与玩家行动权。审核通过的台词原样写入日志并显示。叙事器只能为已有观察选择表达方式。未知索引、遗漏、乱序、额外文本或服务异常会回退到已验证的中文观察。解析或裁决失败则放弃整次行动。
6. 服务端用 `requestId`、基础版本、进程内进行中请求表和 SQLite 写事务提交。世界状态、回合与事件记录共享提交边界。重发同一行动可以取得已提交的结果，过期版本会得到 409。

### 设计决策与边界

- 属性和能力参与裁决；缺少专门技能仍能尝试活动。移动、获取既有证词、调查、布防和有证据的逮捕有明确的持久效果。超出场景表达范围的开放行动只给出低风险的即时反馈。
- 权威世界只接受小集合的类型化操作。物品、身份、生命、NPC 私有知识及历史记录不能由模型直接写入。程序永远不执行模型返回的代码、SQL 或任意 JSON Patch。
- 自定义剧本可以在开场、首次抵达地点、主动寻人，或亲眼看见剧情事件时判定相遇。一次最多引入一人，由引擎登记身份与所在地点。之后的对话、行动和听闻归到同一名角色。普通等候不会逐分钟生成新角色。
- 《王宫疑云》的国王由玩家操控。NPC 的开场、当面回应和异地自主行动由模型决定。公务提供到场时间、地点和职责，赴约得由角色实际走过去。剧本通报宫门换班结果时，也会把已经确认在岗的卫兵登记为可见、可交谈的角色。
- 普通人按群体保存。18 名各部属官参加晨会，240 名河谷居民分批赶集。引擎根据群体日程和游戏时刻计算各地人数，打开存档或回到现场都能得到同一结果。直接向在场群体搭话时，最多从该群体中选出一位持续存在的联系人，保留其个人记忆。
- 国王可从宫门经宫外驿道、河谷村前往河谷行宫。远处人群用同一份群体日程推进。每半个游戏小时，如有远方重要角色的公开公务到期，所有远处地区合计最多发出一次模型请求，处理最多两项职责；落实的移动遵守相邻地点规则。重要世界事件仍在指定时刻发生，玩家只看到自己所处位置能够感知的情况。
- NPC 的行动决策使用它能感知的场景、公开职责和可执行选项。在自定义剧本和《雾港来信》中，其个人目标也会传给它自己的行动决策。台词生成与公开动作审核只使用允许披露的内容。同一游戏分钟内引擎会限制现场自主行动次数，未来计划在原定时刻检查条件。开场生成或审查失败会显示状态提示。第一回合开始前，如果开场尚未执行实际动作，可以点「重试开场」。
- 在同一地点，普通音量的发言和回话会被当时在场的所有活着的角色听见。玩家可以直接问，也可以点名让某人接话；一个回合最多由一名 NPC 决定如何回应。明确向某人耳语时，问话和回话只传给彼此。纪事会在玩家发言旁标出听众。
- NPC 的对话上下文保留自己说过或亲耳听到的最近 16 条可用发言，并区分说话人。重要事件、换人追问和换房不会抹掉已经听见的话，后来到场的人只能听到入场后的发言。旧存档中没有听众记录的交谈只按能确认的直接对话恢复。
- 玩家讲述的内容以原话保留。NPC 的台词引用自己知道并获准披露的事实，并通过审查后，引擎会把这些事实记入实际听众的知识。公开答话时，模型只接收适合该听众范围的事实与对话历史。
- 结构、事实 ID 和状态权限由程序校验。台词语义与事实依据的对应关系由另一条模型请求检查，可能误判。对话草稿被退回后，模型可以改写一次。连续两次未通过语义审核时，正在答话的 NPC 还有一次只依据亲耳听到的对话作答的机会，这次不能传授世界事实。最后仍未通过或接口失败时显示系统提示。听众记得玩家实际说的话，只有通过审查的 NPC 台词才进入对话记忆。
- 普通行动最多耗时 10 分钟，等待可指定未来 12 个游戏小时内的目标。一次请求最多结算六次行动机会。身边有角色或本地人群正在变化时按五分钟推进；安静偏远的地点可以直接推进到下一次半小时结算，中间到期的世界事件照常发生。等待中断后说「继续等待」，可以沿用原来的条件和剩余时间。游戏时钟跟随玩家耗时推进。
- 意图分类、目标理解和开放行动中哪种反应更合理依赖模型质量。模糊的自然语言可能被拒绝或得到保守反馈，玩家可以换一种说法。「王宫疑云」使用有限剧本，主线事件处理后可以继续行动，后续不会自动生成新的政治危机。
- 这是本机单用户应用。SQLite 和场景源码保存完整的客观世界，能读取本机文件的人可以查看秘密。本地模型端点、操作系统和应用服务均属于信任边界。公开多人托管需要另行设计身份认证和存档访问控制。
- 当前按完整世界和回合历史读取，适合中短篇本地游玩。长篇存档可优先扩展时间线分页、历史归档及更多经过验证的情景动作。

## 验证

```sh
pnpm typecheck      # strict TypeScript，涵盖引擎、Provider、服务端、测试与前端
pnpm test           # Vitest，离线且无需 API Key
pnpm build          # 重新类型检查，生成 apps/web/dist
pnpm smoke          # 构建后运行，使用临时 SQLite 和临时本机端口
```

测试覆盖越权声明、物品与身份、撒谎、玩家与 NPC 的信息隔离、时间中断、死亡状态、恶意模型输出、存档重开、重复/并发请求和事务回滚。`smoke` 通过真实 HTTP 请求运行两轮游戏，连接本地 Chat Completions 协议替身，核对生产页面、模型协议、NPC 生成与审查、幂等及快照分支。

配置真实接口后可显式执行 `pnpm test:live-dialogue`。它会创建一个独立存档，实际消耗模型额度，运行开场和五轮对话。脚本检查发出的事实范围、双方逐句历史、模型原文与日志的一致性、台词来源、审查结果以及每回合的状态变化；终端只打印这个存档的玩家可见台词和验证信息。它要求艾琳留在场内并连续开口，若模型选择离场，此项对话专项验收会报告实际结果。

`pnpm test:live-world` 在临时 SQLite 存档中让国王等待并前往宫门。脚本核对异地角色的真实模型决定、持久化的位置、可见范围、旅行中的钟声，以及重复请求是否重做同一时刻的行动。

`pnpm test:live-encounters` 用已配置的真实模型，在独立临时存档中只凭世界信息与当下处境开局，检查新角色的生成、交谈和快照恢复。
加 `--distance` 会沿驿道巡察行宫并原路返回，核对本地人口、远处公务调用次数、宫中事件和回宫人数。
加 `--contact` 会在河谷村向一名居民连续问话，检查其身份、听众和人数守恒。

`pnpm test:live-plans` 使用保存的模型配置，在独立临时存档中连玩十轮。它验证两种查看印玺的说法、引语中的移动、问候兼阅读、艾琳对临时称呼的连续追问、秘密试探、仿品和实际移动。每轮对照模型返回的计划、玩家位置、游戏耗时和世界纪事。

`pnpm test:live-attendance` 在独立临时存档试玩等待与当众询问官员出席情况，核对实际听众及通过审核的模型台词。加 `--retry` 会模拟一次审核服务中断，再让真实模型补答；脚本核对时间、回合、发言、听众以及重复请求的结果。

`pnpm test:live-hearing` 在独立存档等到 08:32 的交接簿通报，然后连续两次不点名发问、向艾琳约定新称呼，再让旁听的罗兰复述。脚本核对现场听众、回复来源、玩家状态和保密试探的结果，只使用议事厅里可公开的内容。

已配置真实模型时，执行 `pnpm test:live-actions` 可另行验证 NPC 自主决策。脚本自行启动测试服务，在临时存档中请求手势、守备和前往花园，核对实际选择、位置和对应观察。NPC 可以拒绝国王的请求。
